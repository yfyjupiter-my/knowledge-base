## 架构咨询：是否引入 Django 后端

- 现状：Next.js 15 App Router + 文件系统 Markdown（content/articles/），零数据库，Fuse.js 客户端检索，单容器 Docker 部署。
- 用户问了两轮：1) 加 Django 管文章是否合适；2) 若做「数据库 + Django」推荐什么技术栈。
- 我的判断：当前阶段不划算（Git 工作流失效、部署从 1 容器变 4 服务、lib/articles.ts 的双语/frontmatter 逻辑要在 Python 重写一遍）。
- 给出若坚持 Django 的推荐栈：保留 Next.js 做前端，Django 6.1 + DRF 3.18 只做 API/Admin/权限；PostgreSQL 17 + Redis 7 + Meilisearch 1.54（中文全文检索，Postgres 原生分词对中文不友好）；Django 6.0 起有内置 background tasks，不必上 Celery；drf-spectacular 生成 OpenAPI → openapi-typescript 给前端出类型。
- 关键提醒：数据模型要设计 Article + ArticleTranslation（对应现在的 .md / .en.md 双语结构）；发布时由 Django 回调 Next.js on-demand revalidate 替代现在的「60 秒生效」。
- 未决：用户尚未说明真实诉求（非技术人员编辑 / 登录权限 / 版本历史与统计），也未开始改造。
